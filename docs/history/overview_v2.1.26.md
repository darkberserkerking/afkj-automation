## 一、18:58 那次失败的根因

```
[点击] 主菜单按钮（nav.playbook） → [点击]「任务」按钮
→ 未识别画面(unknown) ×5 → 连续未识别超限 → 脱离 → 回到「主菜单」
→ [规划] 主菜单 → 世界场景 → 玩法目录 → 到达玩法目录 → 又点主菜单 → 又「任务」
→ 同样绕圈 → 两轮后 [错误] 导航失败：未能进入每日任务界面（54 秒 → failed）
```

**你的判断是对的：无法识别任务界面内的其他标签页。** 具体三条：

| # | 问题 |
|---|---|
| 1 | **任务界面根本没注册** —— `screen_registry` 里没有任何一级标签词 → 停在非「每日任务」标签时全局导航判 `unknown` |
| 2 | `_on_daily_page` 要求标题必须是「每日任务」→ **页面识别与标签判断被混为一谈** |
| 3 | ⇒ 「任务界面开着、但停在别的标签」时，既认不出页面、又去绕导航，来回两轮后放弃 |

### 修法

- **页面判据放宽为「任务界面」**：判据 = 底部**一级标签行**命中 ≥3 个（这一行在任意标签下都常驻）。
  **页面识别不管标签**，标签对不对交给 `_ensure_daily_tab()` 切换。
- **注册 `nav.task_page`**：`screen_registry`（priority 131.6）+ `_SCREEN_LAYER=2` + 中文名「任务界面」+ nav_planner 三条 ESC 出边（与 `nav.friend` 同构）+ `MENU_BY_SCREEN` 登记。

## 二、公会任务页会不会被误判？—— 用你 8 张截图实测：**8/8 零误判**

你给的第 1 张（公会任务）底部的确有「任务」「公会任务」两行文字，**旧判据必然误判**。
我把 8 张图的真实像素 + 真实 OCR 喂给**实际代码**跑了一遍：

| 截图 | 左上角标题 | 取色(每日/公会) | 判定「在每日任务」 |
|---|---|---|---|
| **①公会任务** | `公会任务0` | False / True | **False ✅** |
| ②每日任务 | `每日任务` | True / False | **True ✅** |
| ③翻翻乐 | `翻乐` | False / True | False ✅ |
| ④成长挑战 | `成` | False / False | False ✅ |
| ⑤赛季-阶段目标 | `王都终幕` | **True** / False | False ✅ |
| ⑥⑦赛季(成长任务/阶段) | `赛季里程碑奖励` | False / False | False ✅ |
| ⑧家园目标 | `家` | False / False | False ✅ |

### 实测暴露的两个坑（都已修）

1. **标题带 0.08 太紧** → 漏掉 成长挑战 / 家园目标（标题在 ry≈0.083~0.117）→ 放宽到 **0.12**
2. **标题提取规则错**：原按"最左"取，但副标题行「刷新时间：…」位置**随标签而变**
   （公会任务/翻翻乐在左，每日任务在右）→ 改为按**最上**取 + 排除副标题行
3. **⭐ 新增防线**：取色兜底**必须先确认二级标签行存在** ——
   ⑤赛季任务页在**同一位置**也有自己的橙色子标签（阶段目标/赛季成长任务/赛季阶段），
   若标题恰好读不到，不设防就会误判成"在每日任务"。

> 另外记下：**赛季页标题是当前赛季名**（本次「王都终幕」，下赛季会变）→
> 代码里**不硬编码**该词（已验证打包产物中不含），判据一律用"是否等于每日任务"。

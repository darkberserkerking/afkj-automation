# v2.2.5 交付说明（真机 bug 修复，2026-09-15）

启动游戏报「已就绪」，但窗口其实没激活 → 迷宫任务连续 75 秒截图 0×0 → 导航超时。

```

[17:48:45] [警告] 全局导航超时（目标「玩法目录」）

```

**你的判断「启动游戏后未激活窗口」是对的。**

## 二、根因：三处共同造成，本质是同一个机制

| # | 事实 | 后果 |
|---|---|---|
| 1 | **最小化窗口的 `GetClientRect` 仍返回"还原尺寸"** | `is_game_ready()` 只看尺寸 → **永远检测不出最小化** → 报"就绪"时窗口其实不可截图 |
| 2 | **全项目零处 `IsIconic`** | 最小化状态从未被识别 |
| 3 | 截图前虽调 `activate_window()`（含 SW_RESTORE），但**返回值被忽略** | 恢复失败仍照抓 → 截图区域落在 (-32000,…) 屏幕外 → **0×0** |

> 值得一提的是：代码注释里 v2.0.6 / v2.0.7 反复追过「**窗口矩形正常但截图 0**」这个矛盾，
> 当时归因于坐标系统句柄过期，只打了补丁、没找到根因。这次顺着这条注释线索去查，
> 一次就定位到 `IsIconic` 这个缺失的判据。

## 三、修复（3 个文件）

| 文件 | 改动 |
|---|---|
| `tasks/game_launcher.py` | `is_game_ready()` 增加 **`IsIconic` 判定** → 最小化直接判**未就绪** |
| `tasks/game_control.py` | 新增 `_activate_game_window()`；**启动就绪后显式还原并置前台**（`bot.find_and_focus()`：SW_RESTORE + 双 attach 抢前台 + 前台验证），成功/失败都留日志 |
| `afk_bot/infra/screen.py` | ① `activate_window()` 增加"先确认已脱离最小化"再验前台；② `snap()` 若仍最小化 → **明确告警**「游戏窗口仍处最小化状态 → 本次截图必为 0×0」 |

## 六、请复验

用 v2.2.5 跑「启动游戏 → 异界迷宫」，期望日志：

```
[启动游戏] [成功] 游戏已就绪（画面尺寸有效，等待 15 秒）
[启动游戏] [成功] 已激活游戏窗口 hwnd=XXXXXX（已还原并置前台）   ← 新增
[异界迷宫] [信息] 窗口就绪 hwnd=XXXXXX                          ← 应立刻出现，不再等 75 秒
```

**两种异常情况现在都会明说原因**（不会再出现"静默等 75 秒"）：

- 窗口最小化 → `[警告] 游戏窗口仍处最小化状态 → 本次截图必为 0×0`
- 抢不到前台 → `[警告] 未能把游戏窗口置前台（可能被其它窗口占用前台）——若后续任务截图为空，请手动点一下游戏窗口`

> 补充一句：如果你的使用习惯里**游戏窗口经常会最小化/被别的窗口盖住**，那就属于需要显式保持游戏可见的场景 ——
> 这次修复让工具会主动还原+置前，但如果被**全屏**的其它程序（如视频播放器）抢了前台，工具无法保证一直可见，建议把游戏和工具放在同一块屏幕上。

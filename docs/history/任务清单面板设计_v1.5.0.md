# AFKJ v1.5.0 — GUI 任务清单面板设计文档

> 版本：v1.5.0 适配 | 日期：2026-09-01 | 状态：**设计定稿，待实现**
> 设计原则：**极简** —— 右侧只保留运行日志；核心功能完善的基础上，其他功能越少越好。

---

## 一、设计目标

1. **任务清单化**：把「自动推图」浓缩为清单中的一个任务项，勾选即执行。
   为后续「自动清日常 / 自动推塔 / 女神试炼」等任务预留扩展位。
2. **右侧只剩日志**：不新增连接设置区、不新增实时截图，右侧保持唯一监控 = 运行日志。
3. **零 UI 代码扩展**：新增任务只需写一个 `BaseTask` 子类 + 注册一行，
   清单面板自动渲染出勾选框和参数摘要（`options_schema` / `summary()` 机制已就绪）。

## 二、布局架构

### 2.1 推荐方案 A：左功能 / 右信息

```
┌──────────────────────────────────────────────────────────────┐
│ Header（56px）                                                │
├───────────────────────────┬──────────────────────────────────┤
│ TASKS 任务清单（左，~280） │ StatusBar —— 状态点 / 状态文字   │
│                           │            / 计时器 / 时钟       │
│ ┌───────────────────────┐ ├──────────────────────────────────┤
│ │ ☑ 自动推图        ▲▼ │ │ STATS（幻灵 / 常规 / 推进）       │
│ │   交替模式·逐次战斗   │ │ + 关卡详情卡片                    │
│ └───────────────────────┘ ├──────────────────────────────────┤
│                           │ LOG 运行日志                      │
│  （空态：待添加更多任务）  │ ┌──────────────────────────────┐ │
│                           │ │ [15:02:11] 窗口就绪            │ │
│                           │ │ [15:02:11] 任务启动            │ │
│                           │ │ [15:02:13] 第 1 轮 幻灵        │ │
│                           │ │ ...                            │ │
│                           │ └──────────────────────────────┘ │
├───────────────────────────┴──────────────────────────────────┤
│ 控制栏（▶ 启动 全宽按钮）                                     │
└──────────────────────────────────────────────────────────────┘
```

**布局哲学**：
- **左 = 功能区**（我能做什么 / 我要做什么）—— 任务清单，**只此一项**
- **右 = 信息区**（现在怎么样 / 发生了什么）—— 状态、统计、日志三块堆叠
- 左越窄越能强化"清单很简单"的心智；右越宽越能容纳信息

### 2.2 窗口尺寸

`520×780 → 760×800`（`afk_gui.py:121`）。
理由：右侧要装 **StatusBar（~50px）+ STATS（~120px）+ LOG（剩余）** 三块堆叠，
需 ~460px 宽才不挤；左侧任务行 280px 已够（含 ▲▼）。760 是左右都不勉强挤的最小值。

### 2.3 备选方案 B：保持窗口（不推荐）

若不想改窗口尺寸：StatusBar/STATS 仍顶部全宽，日志右半部分清单左半部分。
极简原则下没意义，不建议。

## 四、任务行组件规格

### 4.1 行结构（高 52px，圆角 10，边框 1px）

```
┌────────────────────────────────────────────┐
│ ☑  自动推图                        ▲  ▼    │
│    交替模式 · 逐次战斗                    │
└────────────────────────────────────────────┘
```

| 元素 | 组件 | 规格 |
|------|------|------|
| 勾选 | `CTkCheckBox`（无文字） | `fg_color=BG_INPUT`，勾选后 `ACCENT` |
| 任务名 | `CTkLabel` | 13px bold，`TEXT_BRIGHT` |
| 摘要 | `CTkLabel` | 11px，`TEXT`（取 `task.summary()`） |
| 排序 | `CTkButton` ×2（▲▼） | 10px，`TEXT_DIM`，透明底，悬停 `BG_BTN_HOVER` |
| 行容器 | `CTkFrame` | 高 52，`BG_CARD`，圆角 10，边框 1px `BG_INPUT` |

**点击热区**：勾选框 + 整行均可切换勾选（行绑定 `<Button-1>`，排除排序按钮区域）。

### 4.2 六态机

| 状态 | 触发 | 行表现 |
|------|------|--------|
| `idle` 待命 | 初始 | 默认样式 |
| `running` 运行中 | 调度器执行到该任务 | 边框 `ACCENT` + 左侧 3px 高亮条 |
| `done` 完成 | `run()` 返回 `'done'` | 勾选旁显示 ✓ `SUCCESS`，摘要追加「完成」 |
| `failed` 失败 | 返回 `'failed'` | ✗ `DANGER`，摘要追加「失败」 |
| `stopped` 停止 | 返回 `'stopped'` | ■ `ORANGE`，摘要追加「已停止」 |
| `skipped` 跳过 | `preflight()` 未过 | 整行 60% 透明，摘要追加「跳过:原因」 |

**状态持久**：一次运行结束后的终态保留到下次「开始」前；下次开始时全部复位 `idle`。

### 4.3 空态

清单里没有启用任务时：显示一行灰色提示
`「未勾选任务 —— 勾选后点击开始」`（`TEXT_DIM` 11px 居中）。
`_on_start` 检测到启用任务数为 0 时拒绝启动并写日志。

## 五、交互流程

### 5.1 启动（F11 / 点击「▶ 启动」）

```
用户勾选任务 → 点击开始
  │
  ├─ 启用任务数 == 0 → 日志提示「未勾选任何任务」→ 拒绝
  ├─ bot 未就绪 → 日志提示（沿用现有 _bot_ready 检查）
  ├─ 正在运行 → 日志提示（沿用现有）
  └─ 通过 →
      ├─ 清单所有行复位 idle
      ├─ _running = True，按钮 →「■ 停止」（沿用现有）
      ├─ 清空日志（沿用现有）
      └─ 启动线程 _bot_thread_wrapper
            └─ 构建 TaskScheduler(bot, logger=_append_log, status_cb=_on_task_status)
                 ├─ 遍历注册表 enabled 任务 → sched.add(TaskCls, options, enabled)
                 ├─ sched.run_all()
                 └─ 结束 → 汇总写日志 + 复位按钮（沿用现有）
```

**关键改动**：`_bot_thread_wrapper` 里 `self._bot.run()` → `sched.run_all()`。
**停止按钮完全不变** —— `_bot.stop()` 会置位 `_stop`，调度器/任务/主循环全部响应退出。

### 5.2 停止

`_on_stop` **不改**（`afk_gui.py:974` 已正确）：
`_running=False → bot.stop() → _reset_buttons → 日志[停止]`。
调度器靠共享 `bot._stop_event` 感知停止，自动中断后续任务。

### 5.3 顺序调整（▲▼）

- 点击 ▲▼ 交换相邻任务顺序 → 立即重排 UI + 写回 `tasks_enabled.json` 的 `order`。
- 一期不做拖拽（tkinter 无原生 DnD，成本高收益低）。

### 5.4 勾选状态持久化

沿用 `TaskRegistry` 既有机制（`task_registry.py`）：
`set_enabled(task_id, bool)` + `save_config()` → `tasks_enabled.json`。
`__init__` 启动时 `TaskRegistry.load_config()`。
（`_on_task_enabled_change` 方法在 `afk_gui.py:626` 已存在，是现成的回调，直接启用。）

### 6.6 `_bot_thread_wrapper`（`afk_gui.py:969`）— 接入调度器

```python
def _bot_thread_wrapper(self):
    # 复位所有任务行 → idle
    sched = TaskScheduler(
        self._bot,
        logger=self._append_log,
        status_cb=self._on_task_status,
    )
    for meta in TaskRegistry.enabled_tasks():
        cls = TASK_CLASSES.get(meta.id)      # 见 6.7
        if cls:
            sched.add(cls, enabled=True)

    results = sched.run_all()                # 阻塞直到全部结束/停止
    self._append_log(f'[信息] 任务汇总: {results}')
    self._running = False
    self.after(0, self._reset_buttons)
```

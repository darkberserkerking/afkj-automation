## 三、关键设计决策

- **清单由 `TASK_CLASSES` 驱动**：`goddess_challenge` 被 `afk_bot/__init__.py:35` 自动注册（default_enabled=True）但一期不接入 → 清单渲染时过滤 `meta.id in TASK_CLASSES`，符合设计文档 §十"TASK_CLASSES 加一行 → 清单自动出现"的扩展哲学
- **六态机**：`running` = ACCENT 边框+2px / `done` = ✓ SUCCESS / `failed` = ✗ DANGER / `stopped` = ■ ORANGE / `skipped` = ⊘ 灰；终态保留至下次开始，开始时全部复位 idle
- **▲▼ 排序**：按钮按设计渲染但 `disabled`（当前仅 1 任务无可交换对象，等后续任务扩展启用）
- **空态提示**：「未勾选任务 —— 勾选后点击开始」，勾选状态动态显隐

## 四、QA 审查与修复（独立验证）

QA 审查 6 个点全过，发现并修复 **1 个 P1**：

> **P1**：`TaskRegistry.enabled_tasks()` 含 goddess_challenge（GUI 不可见不可取消）→ 用户取消唯一可见任务后清单仍"非空"，空态提示永不出现、点开始静默执行 0 任务。
> **修复**：GUI 侧"启用任务"统一定义为 `enabled 且在 TASK_CLASSES 中`（`_on_start` + `_update_empty_hint` 两处），与调度执行集一致。

另修 P2：`_apply_task_status` 行缺失时 `return → continue`（防首命中无行时后续状态不更新）。

QA 另报 2 项历史遗留（非本次改动，未动）：`App.log` 未定义（异常分支会抛 AttributeError）；`dict(self._status)` 与 bot 线程并发风险。

# v2.2.3 交付说明（真机 bug 修复，2026-09-13）

沙漏收益：工具反复补点 → 第 4 次点到了**钻石付费档**。
本版在你补充的判据基础上把「免费次数已用尽」变成**明确可检测**的状态。

---

## 一、你补充的判据（本版核心）

> 「如果读取到的并非 x3、x2、x1，而是 **50、100、200** 这类，说明免费次数用完，需要消耗钻石。」

这条把"免费用尽"从**猜测**变成了**正向检测**：

| 屏幕显示 | 含义 | 工具动作 |
|---|---|---|
| `x3` / `x2` / `x1` | 还有免费次数 | 继续领取 |
| **`50` / `100` / `200`**（无 x 前缀的纯数字） | **免费已用尽 = 钻石定价** | **立即停手，一次都不点** |

## 二、本版改动（在 v2.2.2 基础上）

1. **一次截图同时取两类候选**：xN（`x3`）与钻石定价（`50` 这类纯数字），
   新增 `_nearest_in_range()` 统一「以沙漏图标为锚、取邻域内最近者」的规则
2. **轮询里优先判定价**：一旦出现定价 ⇒ 说明**上一次点击已是最后一次免费领取**
   → 记为生效并收手（**不会漏记次数**）
3. **点击前最后一道闸**：已见定价则一次都不点，日志明说
   `[信息] 沙漏按钮已显示钻石定价 50（免费次数已用尽）→ 停止领取，不消耗钻石`
4. **结束日志如实交代**：
   `[成功] 沙漏收益领取完毕（共 3 次；免费次数已用尽，按钮转入钻石定价 50，未消耗钻石）`
5. 诊断日志追加 `｜钻石定价=50(rx=...,ry=...)`，复发时一眼可见

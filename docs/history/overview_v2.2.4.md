# v2.2.4 交付说明（真机 bug 修复，2026-09-13）

每日任务：**「一键领取」领完了任务奖励，却没领活跃度奖励**（右上角 250 钻石宝箱）。

---

## 一、症状（你的 11:54 日志）

```
[11:54:33] [点击] 「一键领取」（第 1 次） | 图像=(1034, 812)
[11:54:41] [成功] 每日任务领取完毕（一键领取 1 次）
[11:54:41] [调度] 任务结束：每日任务 → 完成
```
`[成功]` 之后**什么都没有** —— 活跃度奖励那一步连一行日志都没留。

## 二、根因：调用顺序和判据都对，坏在「静默 return」+ 取数时机

先说**不是**什么（都逐一核对过）：

| 排查项 | 结论 |
|---|---|
| 调用顺序 | ✅ 正确 —— 一键领取成功后**立即**调 `_claim_activity_rewards()` |
| 判据本身 | ✅ 正确 —— 你给的截图 OCR 实测：「250」在图像 **(1082, 185.5) conf 0.99 / ry 0.181**，完全命中既有判据（`ry<0.25` + `=='250'` + `conf≥0.8`） |

**两个真缺陷**：

1. **读不到就静默 `return`** → 日志零痕迹，既没法定位也没法解释（这是本次最该修的）
2. **`conf≥0.8` 偏严 + 只读一次**：真机这类数字的置信度在 0.78~0.99 波动；
   而**一键领取的奖励弹层**可能还遮着顶部、进度条与宝箱的动画也可能没走完
   → 一帧读不到就直接放弃了

## 三、修复（4 处，全部基于真机实测数据）

| # | 改动 | 实测依据 |
|---|---|---|
| 1 | 新增常量：`_ACT_MIN_CONF=0.60` / 重试 3 次 / 间隔 1.2s / 比例位置 (0.845, 0.181) / 活跃度阈值 100 | 「250」@(1082,185.5)=rx0.845/ry0.181；活跃度「160」@(169,136.5) |
| 2 | 重写 `_claim_activity_rewards()`：**先关弹层**（复用调用方已有帧，不多拍）→ 「250」**重试 3 次**、阈值放宽到 0.6 | 弹层遮挡 / 动画未完成两种失败模式 |
| 3 | **兜底判据**：读不到「250」但**活跃度 ≥100** → 按实测比例位置补点（已领过再点无副作用） | 你明确要求"点右上角 250 处" |
| 4 | **全程留痕**：读到什么、点了哪里、为什么没点，都写日志 | 修掉"静默 return"这个根子 |

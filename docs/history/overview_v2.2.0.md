## ① 停止快捷键 F12

**关键设计（否则这功能等于没做）**：不能用 Tk 的 `self.bind('<F12>')` ——
那种绑定只在**工具窗口有焦点**时触发，而运行时焦点在**游戏**上（工具还会主动把
游戏切到前台）→ 键等于白按。**必须用系统级热键**（`keyboard` 库的全局钩子）。

**调用链**：

```
按 F12（系统级钩子，游戏有焦点也生效）
  → _on_hotkey_stop()      ← 运行在 keyboard 的后台线程
  → _post_ui(...)          ← 投递主线程（后台线程绝不碰 Tk）
  → _do_hotkey_stop()      ← 主线程，带 _closing / _running 双守卫
  → _on_stop()             ← 与点「■ 停止」完全同一条路径
```

- **不抑制按键**：游戏自身仍收到 F12，不改变游戏行为
- 窗口内有焦点时也绑一份（双保险）
- 关闭时自动反注册，不留钩子
- 日志会提示：`[配置] 停止快捷键 F12 已就绪（全局生效，运行中随时可按）`

### ⚠️ 测试当场抓到一个「启动即崩」的 bug

我最初把注册放在 `__init__` 里 `_log_file` 之后 —— 但那时 `self._log_queue` 还没创建
→ 注册时要写日志 → `AttributeError` → **程序启动就崩**。
移到 `__init__` **末尾**才正确。

> 这是构造**真实 `afk_gui.App()`** 的测试才能抓到的（Mock 抓不到）。

### 顺带修掉一个隐患

`afk_bot/auto_farm/loop.py` 里也有一句 `keyboard.add_hotkey('f12', ...)`，
且它在 `run()` **内部** → **每次运行都注册一次** → 回调不断累积（跑 N 次后按一次
F12 会触发 N 个陈旧 stop）。既然 GUI 已全局接管（已核对 `facade.stop() → core.stop()`
能停住引擎），**移除该注册**并加注释说明；连带去掉因此未使用的 `import keyboard`。
测试里加了防回归断言，防止它被加回来。

### BaseTask 契约速查

| 成员                                                              | 用途                                 |
| --------------------------------------------------------------- | ---------------------------------- |
| `run()` → `done`/`failed`/`stopped`                             | **必须实现**，任务主体                      |
| `preflight()` → `(bool, str)`                                   | 执行前检查；返回 False → 调度器标记 `skipped`   |
| `check_completion()` → `(bool, str)`                            | 时间/轮次指标（**OR 逻辑**，任一满足即结束）         |
| `check_stop()` → bool                                           | 检查停止/暂停信号（暂停超时 30s 自动 stopped）     |
| `options_schema`                                                | 参数声明（int/enum/bool/str），GUI 自动生成表单 |
| `summary()` → str                                               | 任务行折叠态摘要（默认拼 options 值）            |
| `on_start()` / `on_end(result)`                                 | 生命周期钩子（可选覆盖）                       |
| `report(progress, detail)`                                      | 进度回报（默认只写日志）                       |
| `self.log(msg)`                                                 | 日志（自动带 `[任务名]` 前缀）                 |
| `self.bot`                                                      | `AFKBot` 实例（facade 全部能力）           |
| `self.options` / `max_time` / `inst_id` / `stats`（v1.8.90 起 max_turns 全链路恢复） | 上下文                                |

**多实例**：同种任务可添加多次（`xxx#1`/`#2`），各自独立配置勾选与指标，由 `TaskRegistry` 管理并持久化到 `tasks_enabled.json`。

### 任务启动定位契约（v1.8.7 起，新增任务强制覆写）

**用户场景**：实际用户可能在**任何界面**开始任务（如直接在「选择烙印」界面启动异界迷宫、直接在备战界面启动自动推图）。工具必须在 run() 第一时间**精准识别当前画面**，并找到**执行当前任务的最优路径**：画面已在任务可执行点就直接续跑，不做无谓的「退回 0 层再重新导航」。界面按层级组织（0层 world/home → 1级 playbook → 2级 任务玩法页 → 任务私有内部态），探测只关心**任务执行域**（2 级玩法页内部态等任务可执行点）。

**机制**：`BaseTask.startup_probe()`（`tasks/base.py`，preflight 之后、run() 的第一个动作），三态返回：

| 返回 | 含义 | run() 行为 |
| --- | --- | --- |
| `'ready'` | 已在任务执行域 | 跳过「导航 + 进入」，直接进任务主循环（最优路径） |
| `'clear'` | 画面不在任务执行域 | 走正常导航流程（默认行为，未覆写时恒返回此值） |
| `'failed'` | 环境异常（如残留弹窗关不掉） | 记日志 + 直接返回 `failed` |

**覆写四规则**（样板实现 = `labyrinth.startup_probe()`，约 tasks/labyrinth.py:625；对齐样板 = auto_farm `_startup_probe()`，afk_bot/auto_farm/loop.py:455）：
1. **执行域判据用任务自己的判定能力**，不依赖 `detect_phase()` 判任务内部态——detector 只负责 0层/1级/2级 通用界面，对任务私有内部态有已验证盲区（v1.7.9 弹窗误判、v1.8.3 续局界面判 unknown 教训）。labyrinth 用自 OCR + `_detect_play_state` 玩法状态机判 door/imprint/shop/battle_prep/victory/failure/boss_cleared。
2. 返回 `'ready'` 后 run() **必须能直接续跑**该界面——主循环各状态分支自带对应动作（命中即推进），不得假定画面会自己回到入口。
3. 探测**尽量复用 run() 原本就要做的第一帧 OCR**（labyrinth 把弹窗清理并入探测同一帧 → 零额外 OCR 消耗，且不破坏干跑测试 texts 序列的帧数预算）。
4. 未覆写默认返回 `'clear'`——简单任务/旧任务自动保持「从 0 层导航」的传统语义，框架升级不改变其行为。

**抽象分层**：auto_farm 的任意界面启动在 **core 导航层**实现——`navigate_to_idle_stage()`（services/navigator.py:429-673）本身就是覆盖全部 phase 的收敛状态机，启动段再用 `_startup_probe()` 短路「已在执行域 → 直接续跑」；labyrinth 在 **task 层**实现——因迷宫内部态 detector 有盲区，由任务自 OCR probe。同一理念、不同实现层，后续新任务按本契约选择对应层的写法即可。

## 5. 踩坑清单

### customtkinter

- `CTkLabel` 默认 `height=28` → **固定高度容器内所有子组件必须显式设 height**
- `fg_color='transparent'` 不是真透明（画父级底色）→ 贴边框内容区**必须 pady 留缝**
- `CTkLabel` 不支持 `border_width`/`border_color`；`CTkFrame.cget('text')` 会 TclError
- `pack_forget()` 后重 `pack()` 排到末尾 → 用 `after=row_frame` 定位
- `winfo_ismapped()` 刚 pack 未渲染返回 False → 统一用 **`winfo_manager()`** 判定
- `pack(side='right')` 是 **LIFO 堆叠**（先 pack 的排最右）
- **`CTkOptionMenu` 底层是原生 `tkinter.Menu`**（v1.8.64/65 实锤）→ `dropdown_*` 参数在 Windows 视觉天花板极低（系统灰白菜单），设什么都"看不出变化"。需要与抽屉风格统一的下拉 → **自建浮层**：CTkButton(▾ 触发) + `tk.Toplevel` 无边框浮窗 + CTkButton 选项 + `grab_set` 模态（参考 `_open_enum_menu`，v1.8.65）
- **短生命周期浮层禁用 `CTkToplevel`**：其构造注册 `after(200/1000)` 回调（图标/缩放），浮层快速销毁后回调撞已销毁窗口 → TclError 错误框弹屏。用 **`tkinter.Toplevel`** 承载 CTk 子部件（完全兼容）
- **`bind_all` 的 tag 含 `#` 解绑不可靠**（如 `<Button-1>#id`）→ 浮层销毁后回调残留、每次开浮层累加一个，持续污染事件循环（诡异崩溃/静默退出元凶）。外点关闭一律用 `grab_set` 模态方案（销毁自动释放），不用 bind_all 外点检测

### OCR / 模板匹配

- 纯图标按钮 OCR 找不到 → 必须**模板匹配 + region 限定**
- PNG 透明背景 `cv2.imdecode` 不处理 alpha → **区分度 = 存在时 conf − 消失时 conf**
- OCR 坐标是截图片区相对坐标 → `click_at` 必须加窗口偏移
- 「世界」按钮文字识别不到（v1.7.0 实测）→ 靠「家园」按钮正向 + 反向推断
- 游戏内文字（「赛季挂机关卡」「挂机收益提升」）是 OCR 关键词，**不要**当普通文案改
- **模板必须传绝对路径**（v1.8.78 真机两次 FileNotFoundError）：`template_match` 直接按入参读盘，裸文件名 `'btn_skip_battle.png'` 会**按进程 CWD 解析**——exe 放桌面时 CWD=桌面，打包资源在 `sys._MEIPASS/templates/`，必然找不到。统一走 `_TEMPLATE_DIR` 常量（同 `btn_back_*`/`btn_door_*`）；`InputController.template_match` 已加 `_resolve_tpl_path` 兜底（裸名 → `_MEIPASS/templates/`，再找不到直接 warn 返回 None，不再抛异常刷屏）
- **frozen 下 `__file__` 不可靠**：模块级资源根统一 `sys._MEIPASS if getattr(sys,'frozen',False) else dirname(dirname(__file__))`（`tasks/labyrinth.py:_PROJECT_ROOT`，v1.8.78）

### 判据设计（v1.8.57~61 沉淀，新增界面判据前必读）

- **句式级排除比界面词表更根本**：描述句「战斗胜利**时**，…」撞胜利弹层标题「战斗胜利」→ 排除 `not h('战斗胜利时')`（描述带「时」标题不带，纯文本特征不受断词/分辨率影响）一词防住商店/门卡/选门全部撞词场景
- **同判据族必须同步排查**：`labyrinth.victory` 与 `goddess.victory_result` 共用 h('战斗胜利')——只修一处会放行到下一优先级再撞（v1.8.57 教训）
- **宽泛兜底词必须有界面域排除**：「之门」兜底被主城建筑「阿瓦隆之门」撞（v1.8.61）→ `HOME_MASK_WORDS`（英雄厅堂/神秘屋/先锋关卡）反向排除；未来新区域带「之门」同理扩此表
- **计数变量防 None 放行**：`floor is None or floor >= N` 的 None 分支 = OCR 波动即裸放行（v1.8.59 第 9 关误选烙印晶球根因）→ 改用累计计数 + 顶栏 UI 校正（UI 为真相源）

### 逻辑 / 测试

- `main loop` 中 `_handle_common_phase` 会消耗 `result` phase → 战斗块需 `_pending_defeat` 兜底
- 主循环按 ESC 会弹「退出游戏」→ 回退要处理退出弹窗
- headless 测试用 `winfo_manager()`；测试内临时实例本节内删干净（否则 KeyError → GIL crash）
- 类属性 `_CONFIG` 勿与模块级变量混淆（测试覆写失效）
- **GUI 冒烟已无人工干预（v1.8.64/65）**：主窗 + 浮层全 withdraw（不上屏不抢焦点）、`sys.excepthook` 恢复默认（不弹崩溃框）、回调异常静默——测试终端无人值守跑完
- **`afk_gui` import 的三大副作用**（测试脚本必防）：① `sys.stderr` 被重定向进 `CRASH_REPORT.log`（traceback 全进日志）；② 模块顶层安装 `sys.excepthook` 崩溃弹窗（挂屏等手点）→ **恢复代码必须放 `import afk_gui` 之后**；③ `os._exit` 不 flush → 异常堆栈用 `print(traceback.format_exc(), flush=True)` 走 stdout，别用 `print_exc()`
- 测试注入停止信号用 **`task._stop = event`**（BaseTask 存的是 `_stop`，不是 `stop_event` 属性）；`_click_text` 内部自 OCR 会消耗一帧 Mock 帧序
- `withdraw` 后 WM 不同步 geometry → 几何类用例先 `deiconify()` + `update()`

### 编辑工具

- **并行 Edit 同一/不同文件会偶发丢更新**（v1.7.0 实测两次）→ 改完必须 grep 复核，别信"Success"就放过
- **Mock 不校验文件存在性 → 路径 bug 只有真机暴露**（v1.8.77/78 教训）：新增模板调用必须在测试里断言"传入绝对路径且 `os.path.isfile`" （见 `test_labyrinth_v1820.py` W 组），否则测试全绿掩盖真机 FileNotFoundError
- **模板 region 必须按窗口比例算，不能绑死像素**（v1.8.79）：真机按钮中心稳定在比例 (0.690, 0.789) ±1px；`region` 参数是**屏幕绝对坐标** → 先 `bot.window_rect()` 拿 (l,t,w,h) 再乘比例。限定后 5 档匹配 **3373ms → 64ms（52×）**，这是高频轮询能成立的前提。拿不到窗口几何时退回 `None`（全屏 + 低频），别硬猜
- **轮询里"贵操作"要拆频**（v1.8.79）：原战斗轮询 = 模板匹配 + OCR，**实测一轮约 5.0s**（maskedNCC 全屏 9 档 3373ms + MaaOCR 整图 451ms + sleep 1.2s），13s 战斗只采样 3 次 → 11 场战斗只点到 2 次「跳过」。改为：跳过检测独立子循环 0.45s/次，OCR 降到 1.2s/次
- **f-string 里的笔误只有跑到那行才炸**（v1.8.79 真机 `name '_qual' is not defined`）：`py_compile` 和 Mock 测试全绿，跑 4 分钟才崩。**提交前必须跑 `python -m pyflakes`（只看 F821 undefined name）**，并把 pyflakes 命令固化（详见 `docs/静态扫描_F821_报告.md`）
- **except 块结束后 Python 会 `del e`**：`except Exception as e:` 里注册 `after(0, lambda: log(f'{e}'))` 这种延迟回调必炸 NameError → 先 `_err = str(e)` 再闭包捕获

## 8. 统一日志规范（v1.8.26 用户定案：全工具强制，新任务必须遵守）

> 来源：auto_farm 分层日志规则归纳推广。GUI 日志区按级别着色，
> 分词提取兼容 `[任务名][级别]` 双前缀（旧 startswith 匹配已废弃）。

### 8.1 级别表（tasks/base.py `LEVEL_PREFIXES` 单一真相源）

| level | 标志 | GUI 颜色 | 用途 |
|---|---|---|---|
| `info`（默认） | `[信息]` | 白（按关键词细分 dim 浅灰/data 中灰） | 过程与状态流转 |
| `ok` | `[成功]` | 绿 #16a34a | 阶段性成功节点（通关/进入/恢复） |
| `warn` | `[警告]` | 橙 #b45309 | 异常但可恢复（将走兜底/重试） |
| `error` | `[错误]` | 红 #dc2626 | 失败/任务终止 |
| `click` | `[点击]` | 青 #0891b2 | 关键点击动作（门卡/按钮，细粒度可选） |
| `data` | `[数据]` | 紫 #7c3aed | 坐标/统计/进度数据 |
| `config` | `[配置]` | 蓝 #2563eb | 配置加载/参数 |
| `debug` | `[调试]` | 浅灰 #9ca3af | 仅 verbose 模式 |

### 8.2 使用规则（任务层）

1. **统一出口**：一切日志走 `self.log(msg, level='info')`（BaseTask），
   auto_farm 走 `self._log(level, msg)`。禁止直接 print / 自拼格式。
2. **格式**：最终渲染 `[任务名] [级别] 内容`（级别标志在前亦可，
   GUI 按括号分词不依赖顺序）；消息内禁止再嵌套第二个级别标志。
3. **兼容**：存量 `self.log('[信息] xxx')` 带标志调用原样合法；
   裸消息自动补 `[信息]`。
4. **新任务 SOP**：新增状态/动作日志时按 8.1 表选级别——
   状态分流用 info、成功节点用 ok、兜底重试用 warn、终止用 error、
   关键点击用 click、坐标统计用 data；不确定就用 info。
5. **GUI**：着色逻辑在 `App._pick_log_tag`（括号分词），新级别需同时
   加 `LEVEL_PREFIXES` 与 `_LOG_LEVEL_TAGS` + tag_config 三处。

### 分支优先级（v1.8.66 新增）

- **主循环里的顶层兜底判断（如烙印晶球替换入口）不能放在某 state 分支之后**——该分支的 `continue` 会把它短路，永远执行不到。烙印晶球替换主界面被 `imprint_fallback`（「确认选择」含「确认」+稀有度≥2）抢判为 imprint → 入口判断上移到 imprint 分支之前才修复
- **入口词必须覆盖界面的所有屏**：烙印晶球替换有主界面（「保留烙印/确认选择」）和二级确认页（「选择已有烙印进行替换」）两屏用词不同——只认二级页词导致主界面漏判（v1.8.61 修复因此未生效）

## 9. 异界迷宫三运行模式（v1.8.93 用户定案，v1.9.0 归纳）

### 9.1 顶栏语义（重要，曾长期理解反）

顶栏 `X/20` 的 **X = 当前所在关卡号**：打完 19 关站在首领门前 = `19/20`；点门进入第 20 关开打 = `20/20`。深层 5 关 = 16/17/18/19/20（首领）。

### 9.2 三模式定义（GUI 运行模式下拉三选一）

| 模式 | options 值 | 核心行为 |
| --- | --- | --- |
| 模式1：通关15结束 | `clear15`（默认） | **不进烙印晶球**（多门时 `_decide_door` 把晶球门 score=(99,1) 排最后；单门只剩晶球仍进）；循环 1→15，15 通关点「结束探索」收尾 → 自动重开 |
| 模式2：20关前停止（单核） | `boss20` | 深层打完 19 关 → 首领门前（顶栏 19/20）查库存：有**执裁之盾** → 任务 `stopped`、画面停在门前零操作（**绝不点结束探索——会清零进度**）；没有 → 打掉首领（无掉落仅积分，游戏自动结算）→ 自动重开下一轮 |
| 模式3：20关前停止（双核） | `boss20_dual` | 同模式 2，达标条件 = 执裁之盾 + 溢出防御 |

### 9.3 首领门前判定（停点机制，防漏停）

- **主判据 = 顶栏 `19/20`**（`_extract_progress`），佐证 = 门卡标题「深层首领/最终一战」；且必须 `state == 'door'`（19 关战斗中顶栏同为 19/20，战斗期不经主循环帧，victory/结算页不得误停）
- **为何不认标题**：v1.8.92 真机 11:39 标题漏读 → 单门兜底把首领打了（无掉落白打）；改为顶栏判定后标题漏不漏读都停
- 达标 → `return 'stopped'`（调度器**中止整个队列**——若希望"达标=完成继续跑后面任务"需改返回值语义，待用户定）；未达标 → 不拦截，落 door 分支点门打首领
- 打完首领游戏**自动结算**（`final_settle` 点屏幕跳过 → done → 重开），全程零收尾操作

### 9.4 烙印库存与记录（模式2/3 核数判定依据）

- 库存 `_orb_inventory` 两个来源：① 进晶球时一次性全列表扫描（之后内存维护：替换成功=删旧加新）；② **晶球关之后**每关烙印三选一 `_handle_imprint` 成功路径调 `_record_imprint_gain(name, qual)` 入账（具名卡 OCR 真名；普通卡「未记录·稀有度」占位——核数只查具名不受影响）

## A7. 模板制作规范

- **动态角标必须去除**（红点/感叹号有/无两态 → 模板失配源）：
  HSV 橙红分割角标（含白描边）+ 膨胀 → **alpha 置 0**；
  ⚠️ **不要填底色**——角标压在人像/图案上时填色会盖掉本体（v1.9.64 踩坑）
- 裁剪范围**不得包含会变化的文字**（xN 次数、倒计时）——沙漏图标裁图即为正面样板
- 制作后必须自匹配校验（score ≈ 1.0）+ 真实截图验证 ≥0.95

## A8. 迂回定位法（十字组合定位）

适用：目标 OCR/模板**双失效**（样式变化/无文字/金色小字），但存在两个可定位参考元素。

步骤：A（与目标同轴）取 **x** + B（与目标同排）取 **y** → 组合 (A.x, B.y) → 画交点图与用户确认。
实例：挂机宝箱 =（时间「XX:XX:XX」中心 x, 沙漏图标模板中心 y）——沙漏模板同时验证可领次数存在。

注意：关联必须来自 UI 固定布局；弹窗/动画中漂移的元素不可用；
日志须打「参考坐标 + 实际点击坐标」双坐标便于微调。

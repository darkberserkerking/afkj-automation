## 问题 1：11 场战斗只点到 2 次「跳过」

### 现象
日志里「战斗中出现「跳过」，点击快进」只出现 2 次，且都在按 F 之后 **11~12 秒**；有一场打了 18 秒也全程没点到。

### 量化排查（实测数据，见 `docs/战斗轮询时序分析.md`）
原轮询一轮的真实开销：

| 环节 | 耗时 |
|---|---|
| `template_match` 全屏 maskedNCC **9 档** | **3373 ms** |
| MaaOCR `_ocr_screen` 整图 | **451 ms** |
| `time.sleep(_BATTLE_POLL)` | 1200 ms |
| **合计** | **≈ 5.0 s / 轮** |

→ 13 秒的战斗只能采样 **3 次**（第 5s、10s 附近），而跳过按钮只在**战斗末段出现约 2~3 秒**，采样窗口直接错过。

### 修复（`tasks/labyrinth.py`）
1. **`_skip_search_region()` 限定搜索区域** — 三张真机战斗截图 maskedNCC val **0.99+**，按钮中心稳定在窗口比例 **(0.690, 0.789) ±1px**；按**比例**（不是像素）圈定 `x∈[0.55,0.85] y∈[0.60,0.95]`
   → **匹配耗时 3373ms → 64ms（52×）**
2. **跳过检测拆成独立高频子循环** `_SKIP_POLL = 0.45s`；OCR 降频到 1.2s（`next_ocr_at` 节流）
3. **收窄缩放带** `(0.7,1.5,0.1)` → `(0.9,1.1,0.05)`（9 档 → 5 档，1883ms）
4. 命中后 `skip_clicked = True`，本场不再重复点
5. 拿不到窗口几何时自动退回「全屏 + 低频」，不硬猜位置
6. 新增 `afk_bot/facade.py::window_rect()` → `(l, t, w, h)`（`template_match` 的 region 要求是屏幕绝对坐标）

**预期**：13 秒战斗可采样 24~28 次，按钮存在的 2~3 秒窗口基本必中。

## 问题 2：烙印晶球 `name '_qual' is not defined` → 整个任务 failed

### 根因
`tasks/labyrinth.py:1750` 的 f-string 日志写错了变量名：

```python
name, old_qual, pos = targets[0]          # 1745 行
self.log(f"[信息] 替换目标「{name}」（{_qual}）")   # 1750 行 ← 笔误
```

v1.8.71 引入。`py_compile` 语法检查、所有 Mock 干跑测试**都抓不到**（要运行到这条分支才炸），真机跑 264 秒才崩在 14:51:09。

**流程走到烙印晶球是正常的**——第 13 关触发替换、第 14 关进门后进的就是替换界面，报错才是 bug。

### 全库体检（pyflakes F821）
顺手对全业务代码做了一次「未定义名」扫描（报告：`docs/静态扫描_F821_报告.md`），A 级（运行必炸）共 **3 处，已全部修掉**：

| 位置 | 问题 | 修复 |
|---|---|---|
| `tasks/labyrinth.py:1750` | `_qual` 未定义 | → `old_qual` |
| `afk_gui.py:805` | `lambda e: _close()`，`_close` 全库 0 定义（按 Esc 关下拉浮层时必炸） | → `top.destroy()` |
| `afk_gui.py:263` | `except Exception as e:` 出块后 Python 会 `del e`，延迟 `after(0, lambda: …{e}…)` 必炸 | → 先 `_err = str(e)` |

### 健壮性增强
`_imprint_orb_flow` 的**主循环**与**收尾**各包一层 `try/except`：任何异常都打日志 + 堆栈，然后照常走收尾（点「继续前进」），**不再把异常抛到调度器把整个任务打成 failed、也不卡在界面里**。

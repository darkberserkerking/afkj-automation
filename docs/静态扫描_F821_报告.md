## 2. A 级清单（真 bug，运行必炸）

| # | 文件:行号 | 名字 | 上下文代码片段 | 疑似正确名字 / 修复建议 |
|---|---|---|---|---|
| 1 | `tasks/labyrinth.py:1750` | `_qual` | `self.log(f"[信息] 替换目标「{name}」（{_qual}）")` | → **`old_qual`**。上一行 `1745: name, old_qual, pos = targets[0]` 已解包出 `old_qual`，本作用域内不存在 `_qual`。 |
| 2 | `afk_gui.py:805` | `_close` | `top.bind('<Escape>', lambda e: _close())` | → **`top.destroy()`**。所在方法 `afk_gui.py:766 _open_enum_menu()` 内只定义了局部函数 `_pick()`（782 行，其收尾正是 `top.destroy()`），全文件无任何 `_close` 定义（仅有 `self._close_task_drawers` 等方法，`_close` 裸名 0 次定义）。用户在该 enum 下拉浮层按 **Escape 键**即炸 NameError。 |
| 3 | `afk_gui.py:263` | `e` | `except Exception as e:` (257) → `self.after(0, lambda: (... self._append_log(f'[错误] Bot 初始化失败: {e}') ...))` (261-266) | 不是笔误，但**是真 bug**：Python 在 `except ... as e` 块结束时隐式 `del e`；该 lambda 经 `after(0, …)` 延迟到主线程事件循环才执行，届时 `e` 已被解绑。实测报 `NameError: cannot access free variable 'e' where it is not associated with a value in enclosing scope`。修复：改成 `lambda e=e:` 或在 lambda 前先 `err = str(e)` 再用 `{err}`。**仅"Bot 初始化失败"分支触发**（故此前未暴露）。 |

### 证据

- 第 1 项：`tasks/labyrinth.py:1745` `name, old_qual, pos = targets[0]`；`1750` 处 f-string 用了 `_qual`。
- 第 2 项：全库 AST 统计"下划线开头名字、引用 > 0 且定义 = 0"只剩两条，其中之一就是 `_close`（另一个是 `_qual`）。
- 第 3 项：已用最小复现脚本在 Python 3.11.15 上实测（延迟执行 → NameError；`lambda e=e` 默认参数捕获 → 正常）。
  pyflakes 同时给出 `afk_gui.py:257:9 local variable 'e' is assigned but never used`（F841），正是"绑定出块即失效"的双子告警特征。

## 6. 结论

- 业务代码（29 个文件）中 **F821 未定义名共 3 处，全部为 A 级真 bug，0 处 B/C 级误报**。
- 其中 2 处是"走不到就永不暴露"的**延迟触发型地雷**，与本次事故的 `_qual` 完全同源：
  - `tasks/labyrinth.py:1750` —— 烙印替换命中该日志语句时必炸（**已确认就是本次真机崩溃点**）。
  - `afk_gui.py:805` —— enum 下拉浮层按 Escape 必炸。
  - `afk_gui.py:263` —— Bot 初始化失败后延迟 lambda 必炸（stderr 吞掉异常，表现为"日志没打出来"而非崩溃，更隐蔽）。
- 正则 + AST 双重专项扫描确认：`_qual` / `_close` 是全库仅有的两个"下划线开头且零定义"的名字，**无其他同类笔误**。

**建议**：把 `python -m pyflakes tasks/ afk_bot/ afk_gui.py task_registry.py maa_ocr.py`（排除 backup）加入提交前检查或 CI，可 100% 拦住本类问题。

# 全局导航能力规范（v2.1.9 提案，2026-09-10）

> 需求来源（用户 22:35）：**精准识别每一个已录入界面/画面 → 确认导航目标 →
> 计算最短路径**；并且：**只要当前处于任务的某个可循环界面序列中，就应可就地
> 开始执行该循环；除非任务对步骤有严格先后要求，则必须从循环起始步骤重来。**
>
> 本文档分三部分：①识别与目标确认判定依据 ②最短路径计算规则 ③"可直入循环
> vs 必须从头"的逻辑条件；最后给出**现状差距与待实施清单**。

## 一、画面识别与目标确认

### 1.1 识别判定依据（现状，已实现）

| 环节 | 依据 | 位置 |
|------|------|------|
| 画面注册 | 每个画面注册 `id` + `判据函数(items)` + `priority` + `desc` | `tasks/screen_registry.py` |
| 判据形态 | OCR 特征词（子串/全等）、多词组合（`h('A') and h('B')`）、反向排除（排除撞词） | 同上 |
| 判定顺序 | **priority 数值越小越先判**（系统弹窗 > 具体页面 > 泛化兜底） | 同上 |
| 层归属 | `_SCREEN_LAYER`（画面 → 层号：0=世界/家园，1=玩法目录/公会，2=玩法主页，3=玩法内部，-1/-2/-3=弹层） | `tasks/global_nav.py` |
| 精确到达表 | `_LAYER_EXACT_SCREEN`（同层多画面时的精确目标画面） | `tasks/global_nav.py` |

**判定顺序原则（必须遵守）**：
1. 先判**系统级弹层**（退出确认 `nav.quit_confirm` priority=200 → 加载 `nav.loading` → 登录 `nav.login`）；
2. 再判**具体页面**（`home.wishlist`、`labyrinth.door` 等 priority 144~150）；
3. 最后判**泛化兜底**（`labyrinth.push_map` priority=150）；
4. 未命中任何判据 → `unknown`（走"转场等待 4 帧 → 脱离链"，不硬猜）。

### 1.2 目标确认（现状，已实现）

| 机制 | 规则 | 位置 |
|------|------|------|
| 目标名 → 目标画面 | `TARGET_SCREENS`（如 `playbook → nav.playbook`） | `nav_planner.py` |
| 等价到达集合 | `TARGET_ALIASES`（如 `world_home` 到达任一 0 层场景即算） | 同上 |
| 到达判定 | `_arrived(screen, cur_layer, tgt_layer, card, target)`：<br>① 层不等 → 未到达；② 有卡片需求 → **必须画面精确相等**；③ 有精确映射 → 画面精确相等（`world_home` 特例为三选一）；④ 无映射 → 到层即算 | `global_nav.py` |
| 特殊到达回调 | `navigate_to(..., arrived_cb=)`：任务可自定义"域内即到达"（如迷宫内部界面） | 同上 |

**判定原则**：**精确优先、层兜底**。同层不同画面（公会 vs 世界）必须用精确画面匹配，防止"假到达"（v1.8.47 已修）。

## 二、最短路径计算规则

### 2.1 图模型

`NAV_EDGES: { 画面id: [(目标画面id, 动作key, 动作标签), ...] }`

- 边 = 一次"可执行动作"（底部直达 / ESC / 卡片点击 / 页签 / 场景互切）；
- **列表中声明顺序 = 同层扩展优先级**（先声明先扩展）。

### 2.2 BFS 与等价路径选择（现状，已实现）

1. **BFS** 求最少步数路径（边权恒为 1）；
2. 同层按边表声明顺序扩展 → 首次到达即"**最少步数 + 同层优先级最高**"；
3. 等价路径策略：**底部直达 > ESC 退回 > 卡片滚动查找**；
4. 仍等价 → 取边表声明顺序靠前者（动作序列字典序最小）；
5. 已在目标画面 → 返回 `([], 0)`，不做任何动作。

### 2.3 执行期动态修正（现状，已实现）

| 机制 | 规则 |
|------|------|
| 偏离重规划 | 执行中实际画面偏离规划的下一步 → **以当前画面为新起点重新 BFS** |
| 不可达降级 | `plan_path` 返回 None（当前画面无出边）→ **贪心规则**兜底（按层差进/退），并打日志「无可达路径…按贪心规则继续」 |
| 未识别处理 | 连续 4 帧 unknown → 脱离链（**ESC 与返回按钮严格交替**） |
| 轮次上限 | `max_iter=14`，`poll=1.2s`；超限失败 → 交下一任务自行收敛 |

## 三、"可直接进入循环" vs "必须从头开始"

### 3.1 概念定义（目标模型，待实施）

每个任务声明**执行域**与**顺序约束**：

```python
class XxxTask(BaseTask):
    nav_target: str = 'playbook'          # 循环起始步骤所在画面（入口层）
    loop_screens: Set[str] = {...}        # 循环内**可直入**的画面集合
    near_screens: Set[str] = {...}        # 「家门口」：差 1 步即可进循环
    loop_entry_strict: bool = False       # True = 步骤严格有序，必须从起始步骤重来
```

### 3.2 判定逻辑（四级决策树）

```
输入：当前识别画面 S，下一任务 T

① T.loop_entry_strict == True
     → 必须从头：导航到 T.nav_target，再执行循环第一步
       （例：需按顺序"领奖 → 校验 → 提交"的任务）

② S ∈ T.loop_screens
     → 可直接进入循环：**跳过任务间导航**，任务从当前界面就地续跑
       （例：迷宫内部（选门地图/备战/烙印选择…）→ 续局）

③ S ∈ T.near_screens
     → 就地推进：不退回入口层，直接执行"进入循环"的那一步
       （例：迷宫主页 → 直接点「进入」，省去"退回玩法目录再点卡片"的往返）

④ 其余
     → 常规导航：BFS 到 T.nav_target（最短路径）
       ※ 若 T 无需前置导航（nav_target 为空）→ 直接执行（v2.1.3 规则）
```

**判定优先级说明**：① 严格顺序**压倒一切**（哪怕当前已处于循环中段，也必须回起点）；
② 优先于 ③（能直入就不必只做"家门口"这一步）；③ 优于 ④（能就地推进就不绕路）。

### 3.3 现状对照（哪些已满足）

| 条件 | 现状 | 差距 |
|------|------|------|
| ① 严格顺序 | **无显式字段**——各任务在 `startup_probe` 内硬编码判断 | 需新增 `loop_entry_strict` 字段并统一 |
| ② 循环可直入 | **已实现**：`startup_probe() == 'ready'` → 跳过导航（v1.8.7）；任务间导航也用它（v2.1.6） | 需把"哪些画面算 ready"从 probe 内部**提取为 `loop_screens` 声明**，使判定可审计 |
| ③ 家门口（差 1 步） | **未实现**——迷宫主页被判 clear → 白绕约 19s（真机 22:29 实测） | 需新增 `near_screens` + 就地推进动作 |
| ④ 常规导航 | **已实现**（BFS + 兜底） | 边表覆盖不全（见 §4） |

## 五、原差距清单（已于 v2.1.9 处理）

### 差距 1：边表覆盖不全（影响"计算最短路径"）

`NAV_EDGES` 目前只描述 **8 个 `nav.*` 画面**的出边；而注册表里已有 **30+ 画面**
（`labyrinth.door` / `labyrinth.imprint` / `home.wishlist` / `nav.friend` /
`nav.loading` / `nav.quit_confirm` / `nav.monthly_reward` …）。任务内部画面**没有出边**
→ 规划必然"无可达路径"，只能靠贪心 + 脱离链慢慢收敛（日志中反复出现）。

**待实施**：为**每个已注册画面**补出边（至少"退回其所属层的入口"），并在 CI 中断言
「注册表里的每个画面都能在 `NAV_EDGES` 找到出边，或用 `TARGET_ALIASES` 直接算到达」
→ 这条断言就是"精准识别每一个已录入画面即可计算路径"的**可验证判据**。

### 差距 2：循环语义隐式、分散

8 个任务的 `startup_probe` 共 **47 个返回点**，判定规则散落在各任务内部，无法统一审计
"哪些画面可直入循环"。

**待实施**：按 §3.1 显式声明 `loop_screens` / `near_screens` / `loop_entry_strict`，
`BaseTask.startup_probe` 提供**统一默认实现**（子类只声明集合，特殊逻辑再覆写）。

### 差距 3：无"家门口"概念（本次真机痛点）

**待实施**：`near_screens` + 就地推进（例：迷宫主页 → 点「进入」），预计省 15~20s/次。

### 差距 4：探测副作用（日志混流 + 重复探测）

任务间导航的直通探测会构造任务实例并调用 `startup_probe`（内部打日志、跑 OCR），
真机表现为：探测日志混入主流 + 任务启动时**重复探测一次**。

**待实施**：探测日志加 `[探测]` 前缀；探测结果缓存并传给任务启动（复用，不重复）。

## 五、验收标准（可执行断言）

1. **识别完备性**：注册表每个画面 id 都能被 `detect()` 在构造帧上命中（已有 29 用例）；
2. **路径完备性**：对任意（已注册画面 × 任意导航目标）组合，`plan_path` 要么给出路径、
   要么明确回报"不可达+原因"（**不得静默走贪心**）；
3. **循环直入**：当前画面 ∈ `loop_screens` 时，任务间导航**零动作**通过（已有 6 用例）；
4. **家门口**：当前画面 ∈ `near_screens` 时，**只执行"进入"这一步**（无退层往返）；
5. **严格顺序**：`loop_entry_strict=True` 的任务，无论当前在循环何处，都从 `nav_target` 重新开始；
6. **偏离重规划**：人为注入画面偏离 → 日志出现「以当前画面重规划」且最终仍到达。

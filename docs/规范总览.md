## 一、代码规范

### 1.1 分层与依赖（**最高优先级**）[来源：手册 §3、代码事实]
```
tasks/            任务层（auto_farm / labyrinth / goddess_trial / home_task / arena / daily_quest / friend_gift / dream_realm / game_control / menu_nav / nav_planner / screen_registry / global_nav）
   ↑ 可依赖
afk_bot/          核心层（facade → auto_farm → services → infra）
task_registry.py  任务注册表（任务层与核心层的中性桥梁）
```
**铁律**：
- **依赖方向只能自顶向下**：`tasks` → `afk_bot`。`afk_bot` **禁止**顶层 `import tasks`。
- 核心层需要使用任务层能力时，只允许**函数内惰性导入**，并 `try/except` 静默降级（不得因缺少任务层能力而崩溃）。
- 中性数据（级别表、常量）应放在 `afk_bot/config.py` 供双方引用，避免形成依赖环。

### 1.2 命名 [来源：代码事实]
| 对象 | 规范 | 现状 |
|---|---|---|
| 模块/包 | 小写 + 下划线 | ✅ 合规 |
| 类 | 大驼峰（`LabyrinthTask`） | ✅ 合规 |
| 函数/方法/变量 | 小写 + 下划线 | ✅ 合规 |
| 模块级常量 | **全大写**（`BACK_THRESHOLD`）；仅模块私有实现细节才加单下划线前缀 | ⚠️ 现存混用（`_BACK_THRESHOLD` vs `BACK_THRESHOLD`） |
| 常量重复定义 | 同一语义常量**只定义一次**，跨模块共享 | ⚠️ 现存 `_SCROLL_REGION`、`_TEXT_TIMEOUT` 等双份 |
| 私有成员 | 单下划线；**任务层不得调用 bot 的 `_` 私有接口**（应经 facade 暴露） | ⚠️ 现存 `bot._ocr_screen()` 25 处 |

### 1.3 错误处理 [来源：代码事实 + 稳定性要求]
- **禁止裸 `except: pass`**。至少记录 `warn` 级日志（含异常摘要）。
- 禁止用魔法值掩盖失败（如 OCR 失败置 `[]` 或 `999`）——要么上抛，要么记为 warn 并进入安全分支。
- "检测失败"不得等价于"检测通过"（网络/窗口/截图失败必须按失败处理）。
- 持有锁/句柄/临时资源的路径必须 `finally` 释放。
- 公开入口（`facade`）应有兜底异常，避免异常穿透到 UI 回调。

### 1.4 注释与文档 [来源：代码事实]
- 模块必须有 docstring，且**描述当前结构**（禁止出现已不存在的文件名如 `core.py`）。
- 注释正文用**中文**（日志同理，用户定案）；技术术语（API 名、库名）可保留英文。
- 变更处必须写版本标记与原因，格式：`# vX.Y.Z：<原因> —— <做了什么>`。
- 删除代码时同步删除其注释（避免过时注释）。

### 1.5 复用约定 [来源：代码事实]
- 两个及以上模块出现同构逻辑（导航、重试、OCR→点击三段式）→ 抽到 `tasks/base.py`（任务层）或 `afk_bot/config.py`（中性常量）。
- 等待统一走 `wait_until(cond, timeout)` 工具，禁止各写 `for _ in range(n): sleep()`。

### 1.6 配置与常量 [来源：代码事实]
- 阈值、超时、重试次数**集中**在 `afk_bot/config.py`，禁止行内魔法数字（`min_conf=0.6` 之类必须引用常量）。
- `time.sleep()` 必须走统一的等待工具（可中断、可日志）。

### 1.7 类型注解 [来源：代码事实]
- 所有公开方法必须有参数与返回注解；`dict` 契约过宽时应定义 `TypedDict` 或至少 `Dict[str, Any]`。
- 目标：新代码 100%，存量代码每次触碰补齐。

### 1.8 目录卫生 [来源：代码事实]
- 根目录只允许：源码、配置、文档 `docs/`、构建入口 `*.spec`。
- 临时产物（`_tmp_*`、`*.log`、运行日志）不得留在根目录；历史报告归档 `docs/history/`。
- 必须有 `.gitignore` 忽略 `__pycache__/`、`build/`、`dist/`、`backup/`。

## 二、日志规范

（基准：`docs/开发指导手册.md` §8，v1.8.26 用户定案；级别表单一真相源）

### 2.1 级别表 [来源：手册 §8.1]
| level | 标志 | GUI 颜色 | 用途 |
|---|---|---|---|
| info | `[信息]` | 白 | 过程与状态流转 |
| ok | `[成功]` | 绿 | 阶段成功（通关/进入/恢复/任务完成） |
| warn | `[警告]` | 橙 | 异常但可恢复 |
| error | `[错误]` | 红 | 失败/终止 |
| click | `[点击]` | 青 | 关键点击动作 |
| data | `[数据]` | 紫 | 坐标/统计/进度 |
| config | `[配置]` | 蓝 | 配置加载 |
| debug | `[调试]` | 浅灰 | 仅 verbose |

### 2.2 格式 [来源：手册 §8.2 + 代码事实]
- 统一走 `self.log(msg, level=...)`（`tasks/base.py`），**禁止**消息内再嵌第二个级别标志（避免 `[信息] [成功]` 双重前缀）。
- 级别表**只有一份**：`afk_bot/config.py :: LEVEL_PREFIXES`（中性层，供 tasks 与 afk_bot 共用）。
- 禁止 `print()` 输出日志；无 logger 注入时降级为**静默**，不得降级为 print。
- `_log` 契约统一为 `(level, msg)`，跨层调用需确认目标模块契约，避免参数错位。

### 2.3 中文化 [来源：用户定案 v1.8.32]
- 用户可见日志**尽量全中文**。screen_id / phase / 模板名 / 目标 key 等英文标识必须经中文映射（`zh_screen` / `_phase_zh` / `_tpl_zh` / `zh_target`）后再输出。
- 新增界面 id 必须**同步登记中文名**，否则兜底会漏出英文。

### 2.4 关键埋点 [来源：手册 + 代码事实]
必须留痕：任务启动/结束、导航每一步、关键点击、异常兜底、收到停止信号。
**静默分支（return/continue 无日志）视为缺陷。**

### 2.5 脱敏 [来源：代码事实]
- 日志禁止出现本机绝对路径：路径类信息只输出 `os.path.basename()`。
- 禁止整段 traceback 入日志（如需，只取异常类型与消息，或末行且去掉路径）。
- 窗口句柄 `hwnd=` 等内部数值改为语义描述（如「窗口已绑定」）。

### 2.6 降噪 [来源：代码事实 + 真机日志]
- 循环中的状态日志**仅在状态变化时打印**（缓存上一次值比对）。
- 主循环每轮无条件打印同文案属缺陷。

### 2.7 任务归属 [来源：代码事实]
- 任务层自动带 `[任务名]` 前缀（`BaseTask.log`）。
- 调度器日志需带 `[调度]`；GUI 自身消息带 `[界面]`。

## 三、GUI 设计规范

（基准：`afk_gui.py` 现有常量体系；判据截图 `C:\Users\x9502\Pictures\Screenshots\时间轮次.png`）

### 3.1 布局与间距 [来源：代码事实]
- 4px 基准间距体系（`SPACE_XS=4 … SPACE_XXL=24`），**禁止**行内 `padx=5` 之类魔法值。
- 布局方式以 `pack` 为主；网格排布用 `grid`；`place` 仅限浮层（抽屉/拖拽预览）。
- 容器关键尺寸（宽度阈值、行高）需命名常量，禁止内联数字。

### 3.2 配色与字体 [来源：代码事实 + 截图]
- 颜色**全部**取自常量表（`afk_gui.py` 顶部 `MaaEnd` 浅色风格 18 色），派生语义色（如 danger hover）必须**补充进常量表**，不得内联 hex。
- 日志 tag 色板并入主配色常量表，不得独立游离。
- 字体：族名统一常量（`FONT_FAMILY`），字号按层级命名（`caption/body/subtitle/title`），现存 7 档字号收敛为 4 档。
- 已定义未使用的常量视为死代码，应删除。

### 3.3 组件复用 [来源：代码事实]
- 出现 2 次以上的控件组合 → 抽自定义组件（`CTkFrame`/`CTkButton` 子类），如 `DangerCloseButton`、任务行卡片、抽屉容器。
- 禁止同一面板的多份实现风格不一致（现设置抽屉用原生 `tk.Frame`，其余用 CTk）。

### 3.4 交互反馈 [来源：代码事实]
- 长任务执行期间：按钮置 `disabled`，并有文字/状态反馈（不得仅靠日志软拦截）。
- **线程安全**：工作线程一律通过 `self.after(0, ...)` 回写 UI（现状合规，需保持）。
- 日志区自动滚动需支持"用户上翻时暂停自动滚动"。

### 3.5 异常提示 [来源：代码事实]
- 日志区是主要错误出口（零打断设计，保留）。
- **异常处理器自身不得有缺陷**（如调用不存在的方法）。
- 输入校验优先行内提示（红框/说明文字），其次日志。
- 持久化失败（配置损坏/磁盘只读）必须**有感知**（至少一条 warn），不得静默。

### 3.6 主题与适配 [来源：代码事实]
- 新控件必须适配已设定的 appearance mode（当前固定 light）；原生 tk 控件需同步主题色。
- 控件尺寸（高度/圆角）按语义分档，禁止任意值。
